# DIRECTOR_PLAYBOOK — أسلوب التوجيه

## المبادئ العامة

1. **لا تخمين** — عند أي التباس، اسأل قبل التنفيذ
2. **وثّق كل قرار** — DEC أو CR أو OD
3. **تحقق قبل التنفيذ** — الوكيل يطرح خطة، ثم ينفّذ
4. **اختبر على جهاز حقيقي** — لا محاكي للميزات الحرجة
5. **commit صغير متكرر** — خطوة → commit → خطوة

## نمط الجلسة

### البداية
1. اقرأ `NEXT_SESSION.md`
2. اقرأ `PHASE_PROGRESS.md`
3. اقرأ `SESSION_HANDOFF.md` (آخر 3 إدخالات)
4. اقرأ ملفات المرحلة الحالية

### قبل الكود
- الوكيل يطرح:
  - OD المفتوحة التي تعطّل
  - قائمة الملفات
  - الحزم المطلوبة
  - أول 3-5 خطوات
- المدير يراجع ويوافق
- لا يبدأ الكود قبل الموافقة

### خلال التنفيذ
- بعد كل ملف: `flutter analyze --fatal-infos`
- بعد كل خطوة منطقية: `flutter test`
- عند أي فشل: توقف، لا تتجاوز (Stop Rule 09)
- كل خطوة: commit منفصل

### النهاية
- commit + push
- تحديث `SESSION_HANDOFF.md` (Session N)
- تحديث `PHASE_PROGRESS.md`
- إغلاق نظيف

## قواعد صارمة

### Rule 019 — Reproducibility
- SHA pinning في CI (لا `@v4`)
- إصدارات exact في pubspec (لا `^`)
- Flutter version مثبت

### Rule 020 — Human Approval
- لا تعديل `approvals.yaml` من الوكيل
- القرارات القانونية/الشرعية بشرية

### Stop Rules 1-17
- الوكيل يتوقف عند أي التباس
- تقرير فوري، لا تخمين

### DEC-0018 — Phase-Aware CI Rollout
- CI jobs تدريجية حسب المرحلة
- Phase 00: 5 jobs
- Phase 05+: كامل

## أسلوب المراجعة

### عند فشل اختبار
1. **لا تتجاوز** (Stop Rule 09)
2. اطلب:
   - الناتج الحرفي
   - الفرضيات
   - خطة الإصلاح
3. راجع الفرضيات
4. وافق على إصلاح محدد

### عند طلب حزمة جديدة
1. تحقق من pub.dev
2. اطلب: الإصدار + الترخيص + تاريخ النشر
3. قارن بالبدائل
4. قرر (APPROVED / CR)

### عند اكتشاف مشكلة معمارية
1. افتح CR
2. وثّق: قبل/بعد/السبب/الأثر
3. اعتمد
4. عدّل الوثائق المتأثرة

## نبرة التواصل

- **واضح ومباشر** — لا مجاملة
- **مبني على الدليل** — "لأن..." لا "أعتقد..."
- **تصحيح فوري** — إذا أخطأ الوكيل، صحّح
- **اعتراف بالخطأ** — إذا أخطأت أنت، اعترف (مثل receivers في 00B)

## دروس مستفادة (من Phase 00 + 00B)

1. **Receivers يدوياً مطلوبة** (DEC-0023) — لا تثق بالتوثيق، افحص merged manifest
2. **ColorOS/Oppo** — إعدادات إلزامية للمستخدم
3. **Hive isolate** — `IsolateNameServer` + `SendPort` (لا `path_provider` في الخلفي)
4. **FakeAsync + MethodChannel** = deadlock — استخدم dependency injection
5. **CI أخضر ≠ كود صحيح** — اختبر على جهاز حقيقي
