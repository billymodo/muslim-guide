# Phase 02 — Prayer Times & Location

## Status
PLANNED

## Objective

حساب مواقيت الصلوات الخمس محلياً بلا شبكة، مع دعم:
- GPS أو اختيار يدوي لمدينة.
- طرق حساب متعددة وفق DEC-0028.
- اختبار خمس مدن مرجعية على الأقل.
- الحالات الحدّية: خطوط العرض العالية، DST، ومناطق زمنية مختلفة.
- العمل في وضع الطيران.

## Scope

### داخل النطاق
- Domain نقي لحساب المواقيت (بلا Flutter).
- Location service (GPS + يدوي).
- شاشة `PrayerTimesScreen` (SCREEN-005).
- شاشة اختيار الموقع (SCREEN-006).
- إعدادات: طريقة الحساب، مذهب العصر، وطريقة خطوط العرض العالية.
- اختبارات وحدة شاملة (Domain).
- اختبارات widget للشاشات.
- اختبار على جهاز حقيقي (Pixel 6a أو Redmi Note 12).

### خارج النطاق
- الإشعارات (Phase 04).
- الأذان الصوتي (Phase 04).
- القبلة (Phase 03).
- التقويم الهجري (Phase 08).
- اختيار طريقة الحساب تلقائياً حسب البلد.

5. **OD-0019** — محسومة في **DEC-0017**: Pixel 6a أساسي وRedmi Note 12 ثانوي.

### قبل بدء الشاشات
6. `geolocator` — يحتاج CR-0009 مع مراجعة pub.dev والترخيص وتثبيت إصدار دقيق.

## Implementation Tasks

### Task 1 — Domain (2-3 أيام)
1. تعريف `CalculationMethod` (MWL, Egyptian, UmmAlQura, Karachi, ISNA, Tehran, Jafari).
2. تعريف `AsrMethod` (Standard, Hanafi).
3. تعريف `HighLatitudeRule` (MiddleOfNight, SeventhOfNight, TwilightAngle, None).
4. تطبيق `PrayerCalculator` استناداً إلى PrayTimes.org.
5. كتابة اختبارات وحدة شاملة (30 حالة أو أكثر).
6. التحقق من النتائج مقابل خمس مدن مرجعية على الأقل.

### Task 2 — Cities Data (0.5 يوم)
1. إعداد بيانات GeoNames لما لا يقل عن 100 مدينة.
2. تحويلها إلى JSON وفق schema موثق.
3. تسجيل checksum.
4. كتابة `CitiesLoader` واختباره.

### Task 3 — Location Service (1 يوم)
1. إضافة `geolocator` بعد اعتماد CR-0009.
2. طلب صلاحيات وقت التشغيل بعد اعتمادها.
3. تنفيذ `LocationServiceImpl` لدعم GPS والاختيار اليدوي.
4. معالجة رفض الصلاحية بالرجوع إلى الاختيار اليدوي وإرشاد المستخدم.

### Task 4 — Application Providers (1 يوم)
1. `locationProvider` (Notifier, keepAlive).
2. `calculationMethodProvider` (Notifier, keepAlive).
3. `prayerTimesProvider` (AsyncNotifier, autoDispose).
4. `countdownProvider` (Stream, autoDispose) — يعمل المؤقت في foreground فقط.

### Task 5 — Screens (1.5 يوم)
1. تنفيذ `PrayerTimesScreen` وعناصرها.
2. تنفيذ `LocationPickerScreen`.
3. ربط الشاشات بالـ Router.
4. كتابة اختبارات widget للحالات والسلوك.

### Task 6 — Device Testing (0.5 يوم)
1. اختبار على Pixel 6a أو Redmi Note 12.
2. اختبار انتقال DST.
3. اختبار وضع الطيران.
4. اختبار رفض صلاحية الموقع.
5. توثيق النتائج.
