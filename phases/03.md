# Phase 03 — القبلة (Qibla)

> **معتمد من المدير 2026-10-09 (تعديلات E-1..E-8) — Status: ✅ APPROVED — 2026-10-10.**

## Status
✅ APPROVED — 2026-10-10

## Objective

حساب وعرض اتجاه القبلة من موقع المستخدم بدقة مقبولة (REQ-QIBLA-001) عبر
بوصلة تفاعلية تعمل offline بالكامل، مع بديل رقمي واضح عند غياب الحساس
المعغناطيسي أو ضبطه. إضافةً لذلك: إغلاق الالتزامات المنقولة من ما بعد
Phase 02 (OD-0028، GAP-meta-caret، hive_ce patch، GAP-license-page).

## Scope

### داخل النطاق
- شاشة القبلة (`QiblaScreen` — UI_VISION وصفة 5): بوصلة `CustomPainter`
  + قراءة رقمية بالدرجات + semantic label + حالات (Loading / No-sensor /
  Error / Success / Calibrating).
- **Domain نقي** لحساب اتجاه القبلة (bearing إلى الكعبة المشرّفة)
  رياضياً — بلا Flutter، قابل للاختبار بقيم مرجعية.
- Application providers: `compassProvider` (Stream)،
  `sensorStatusProvider`، `qiblaDirectionProvider` — عبر طبقة abstraction
  مُزيَّفة قابلة للاختبار (درس Phase 02: لا MethodChannel مباشر في UI).
- **البديل الرقمي** عند غياب الحساس: نص/رقم عن الاتجاه (REQ AC).
- المهام المنقولة (Task 1–4 أدناه).
- خلفية الشاشة: **gradient placeholder** (نفس نمط Phase 02 hero —
  قرار المدير؛ `qibla_bg.webp` مؤجل).

### خارج النطاق
- أصل `qibla_bg.webp` و`kaaba_badge.webp` (GAP-qibla-bg — Phase 05+).
- الإشعارات والأذان (Phase 04) · الأذكار (Phase 05) · القرآن (Phase 06).
- تحديد موقع جديد — يُعاد استخدام `locationProvider` الحالي (Phase 02).
- AR/معلمات حساس إضافية (gyroscope fusion) ما لم يفرضه اختبار الدقة.

## Deviations from Specification
- **AndroidManifest intent filter لـ `/qibla`:** أُضيف أثناء Task 10 (بعد أن لم يفتح deep link على الجهاز). التغيير: `<intent-filter>` مع `scheme="muslimguide"`, `host="test"`, `path="/qibla"`. لا صلاحيات جديدة. **الإجراء الإداري:** لم تُعطَ موافقة صريحة مسبقة — قبول استثنائي + تسجيل للتعلّم. موصى بـ: توحيد نمط deep links في Phase 04+ (wildcard بدل path-specific).
- **Task 9.5 — no-sensor stream contract:** `FlutterCompass.events == null`
  now emits one `null` heading so the numeric fallback is reached; notifier
  completion without a heading defensively marks the sensor unavailable.
  This regression fix was required to satisfy REQ-QIBLA-001 (`a50fc45`).
- **CR-0011 execution:** `flutter_compass 0.8.1` was selected and exact-pinned
  as approved; this is the approved package decision, not a spec deviation
  (`223f28c`).
- **Task 10 device constraints:** no-sensor was verified with fakes only
  because the Oppo A95 has a magnetometer; Test B was skipped by Director
  approval after Test A passed. Non-fatal Oppo/Android log warnings and a
  slow cold-start frame are recorded in `docs/phase-03-device-testing.md`.
